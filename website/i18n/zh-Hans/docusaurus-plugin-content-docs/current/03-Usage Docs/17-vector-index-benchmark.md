# 向量索引基准测试

> 本文档基于 2026-11 重新构建和检索的结果完整重写。旧版 upsert/rebuild 结果已全部废弃。
> 本轮只测试**构建和索引检索**，不测试 upsert/增量维护。

## 1. 结论摘要

四个标准 ANN 数据集在 RaBitQ `bits=7` 下都能达到 **recall@100 ≥ 0.97**，代价是需要更大的 `nprobe`。
主要权衡是 `bits=7` 与 `bits=1`、缓存大小（尤其 exact 重排）以及接口。

| 数据集 | 配置 | recall | index 单查 QPS | index batch QPS |
|---|---|---:|---:|---:|
| SIFT-128 | nlist=256, bits=7, nprobe=64 | 0.970 | 379.4 | 4128.9 |
| GloVe-200 | nlist=4096, bits=7, nprobe=2048 | 0.972 | 114.1 | 591.5 |
| GIST-960 | nlist=256, bits=7, nprobe=32 | 0.974 | 157.7 | 1709.2 |
| Deep-Image-96 | nlist=1024, bits=7, nprobe=32 | 0.971 | 22.9 | 121.7 |

## 2. 测试方法

| 项目 | 取值 |
|---|---|
| 存储 | 本地 file store（不是 MinIO/S3） |
| 索引 | IVF + RaBitQ，`hash_bucket_num=4` |
| top_k | 100 |
| recall | 对 HDF5 ground truth 的 recall@100 |
| RSS | 构建/查询进程 `VmRSS`；pgvector 另列服务端 RSS |
| 构建 | 独立 build 进程，不含写表阶段峰值 |
| 清理 | 每个数据集测完 drop 表、删除本地 index/cache |

| 数据集 | Base | Query | GT | dim | 距离 |
|---|---:|---:|---:|---:|---|
| SIFT-128 | 1,000,000 | 10,000 | 100-NN | 128 | L2 |
| GloVe-200 | 1,183,514 | 10,000 | 100-NN | 200 | cosine |
| GIST-960 | 1,000,000 | 1,000 | 100-NN | 960 | L2 |
| Deep-Image-96 | 9,990,000 | 10,000 | 100-NN | 96 | cosine |

缓存/接口表中每格格式为 **单查 QPS / 平均 ms / RSS MB / recall**。
单查 QPS 是去掉首次查询后的稳定值；batch QPS 是两轮平均。

观察：

- index-only 对缓存大小不敏感，512MiB 主要增加延迟；
- exact 重排受 block cache 影响很大：512MiB → 1GiB → 8GiB，batch 提升明显
  （SIFT 148 → 223 → 2307 QPS；GIST 14 → 59 → 1019；Deep 7.1 → 63 → 139）；
- 完全关闭缓存时 index-only 仍可工作；exact 单查走 fallback（GloVe 高 recall 配置约 1 QPS），
  但 native exact batch 未实现：`exact batch search could not open data file`。

## 7. 并行度与 bucket 数

SIFT，目标配置，Python native，cache 8GiB，NQ=20：

| parallelism | index 单查 QPS | index batch QPS |
|---:|---:|---:|
| 1 | 378.6 | 4301.7 |
| 2 | 325.4 | 2643.1 |
| 4 | 379.4 | 3190.7 |

native batch 已经按 bucket 并行探测；短 batch 再增加 `parallelism` 会超订阅。
建议让 `hash_bucket_num × vector_search.parallelism` 接近 CPU 核数。

## 8. 选型建议

| 目标 | 建议 |
|---|---|
| recall/QPS 平衡 | bits=7，nprobe 取 0.97 拐点，见目标表 |
| 最小内存 | 512MiB 缓存：index-only 可用，exact 很慢 |
| exact 重排 | 8GiB L1/L2；512MiB 不适合 batch |
| Python native | 用 `batch_search`；短 batch 设 `parallelism=1` |
| SQL | DataFusion 单查接近 native；SQL batch 慢于 native batch |
| pgvector | 服务化方便，但 exact 昂贵且需要数 GB RSS |

## 9. 限制

- 本地 file store，不是 S3/MinIO；绝对 QPS 与远程存储不同。
- 大多数结果 NQ=10（SIFT 参数扫描 NQ=20）；QPS 为稳态值。
- GloVe 高 recall 配置 NQ=10 时 recall 0.972，更大的 NQ=20 参数扫描为 0.977。
- pgvector 不同缓存大小只在 GloVe 高 recall 配置上测了 512MiB/1GiB/8GiB；
  其它 pgvector 接口结果使用 8GiB。
- 未报告 `index_bytes`：多配置构建时旧 index generation 仍在磁盘上，构建时间和 RSS 不受影响。
- 中文和英文页面使用同一批原始数据；如需更新应同时重生成。
