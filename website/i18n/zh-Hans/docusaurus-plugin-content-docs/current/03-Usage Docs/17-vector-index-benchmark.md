# 向量索引基准测试（构建 + 检索）

> 本文档是 2026-11-11 重新跑出的结果；旧版 upsert/rebuild 场景结果不再使用。
> 本轮**不测试 upsert/增量维护**，只测试构建和索引检索。

## 1. 范围

- 数据集：SIFT-128、GloVe-200、GIST-960、Deep-Image-96（9.99M）。
- 距离：SIFT/GIST 为 L2；GloVe/Deep 为逐行 L2 归一化后的 inner product，排序等价 cosine。
- 构建：nlist=256/1024/2048/4096，total_bits=1/7。
- 检索：不同 nprobe、index-only / exact、单查询 / native batch / SQL batch。
- 接口：Python native、DataFusion SQL、pgvector（`postgres-lakesoul`）。
- 缓存：L1 512MiB / 1GiB / 8GiB，L2 512MiB / 1GiB / 16GiB，以及关闭缓存。
- 并行：native batch `parallelism=1/2/4`；表 `hash_bucket_num=4`。
- 每个数据集测完立即 drop table、删除本地 index 和 cache，再进入下一个。

## 9. 结论

1. **构建**：SIFT 3.5–7 s，GloVe 8–53 s，GIST 34–54 s，Deep 94–141 s；
   build RSS 约 0.48–1.47 GB。
2. **recall 0.97 是可以达到的**，但需要 bits=7 和提高 nlist/nprobe：
   - SIFT：nprobe=64（nlist=256）；
   - GloVe：nprobe=1024（nlist=2048）；
   - GIST：nprobe=32（nlist=256）；
   - Deep：nprobe=32（nlist=1024）。
3. **bits=1 在相同 nprobe 下 recall 明显不足**：SIFT 约 0.55，GloVe 约 0.45，
   GIST 约 0.74，Deep 约 0.53。
4. **exact 对缓存最敏感**：
   - SIFT exact batch 从 148（512MiB）提升到 2307（8GiB）；
   - GIST exact batch 从 13.7 提升到 1019；
   - Deep exact batch 从 7.1 提升到 139。
5. **缓存关闭**时 index-only 仍可工作，但 SIFT 单查约 5 QPS、batch 约 106；
   exact batch 不支持。
6. **接口**：DataFusion 单查通常接近 Python native；pgvector 额外有协议/服务端开销，
   exact batch 最慢。pgvector exact 服务端 RSS 可达数 GB。
7. **bucket_num=4 + eager（小索引）/lazy（Deep）** 是本轮达到高 QPS 的关键；
   旧结果中的 400–500 单查、数 k–10k batch 与当前 SIFT 结果一致。
