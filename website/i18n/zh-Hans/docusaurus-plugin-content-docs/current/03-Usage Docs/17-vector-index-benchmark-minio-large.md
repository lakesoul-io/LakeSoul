# 向量索引大规模基准（MinIO）

> 本页是 **L1 8GiB / L2 16GiB** 版本；**L1 512MiB / L2 1GiB** 版本见 [17-vector-index-benchmark-minio-large-512m1g.md](17-vector-index-benchmark-minio-large-512m1g.md)。
>
> 单查使用 **200 条 query**；batch 使用 **全部 query**
> （SIFT/GloVe/Deep 10,000 条，GIST 1,000 条）。只测 MinIO 构建 + 检索。

## 1. 方法

| 项目 | 取值 |
|---|---|
| 存储 | MinIO `s3://lakesoul-bench2` |
| 缓存 | L1 8 GiB + L2 16 GiB，标 "off" 的除外 |
| 索引 | IVF + RaBitQ，`hash_bucket_num=4` |
| 单查 | 去掉首次查询，再测 200 条 |
| batch | 全部 query 向量一次 native batch（或一次 SQL/pgvector 遍历） |
| P50/P90/P99 | 单查为真实逐条延迟；batch 为 100 条 chunk 归一化近似 |
| CPU/内存 | 16 逻辑 CPU / 8 物理核 / 60 GiB；未绑核 |
| 清理 | 每个数据集测完 drop 表，删除 MinIO prefix 和 cache |

| 数据集 | nlist | bits | build s | build RSS MB | 写表 s |
|---|---:|---:|---:|---:|---:|
| SIFT-128 | 256 | 7 | 14.5 | 496 | 3.0 |
| GloVe-200 | 1024 | 7 | 58.6 | 830 | 13.2 |
| GIST-960 | 256 | 7 | 53.2 | 1068 | 41.6 |
| Deep-Image-96 | 1024 | 7 | 147.0 | 1434 | 56.4 |

## 5. 说明

- batch 的 P50/P90/P99 由 100 条 chunk 归一化得到，包含 batch 调度开销，
  不是严格的单请求服务延迟。
- GIST 只有 1,000 条 query，所以 batch 为 1,000。
- GloVe 在 200 条单查下 nprobe=448 只有 0.9682；改用 nprobe=512 后 0.9713。
- Deep-Image nprobe=64：index recall 0.9687，exact 0.9895。
- 每个数据集测完都已释放表/索引/cache。
